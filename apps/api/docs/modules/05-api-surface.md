# API 资源与接口面

这份文档把 API 层的路由面先规划出来。它不追求把所有细节一次写死，但要保证模块划分和 Web 侧需求能对上。

---

## 1. 路由风格

建议采用按领域划分的 REST 接口面，例如：

- `/api/auth`
- `/api/me`
- `/api/tenants`
- `/api/content`
- `/api/learning`
- `/api/commerce`
- `/api/licenses`
- `/api/devices`
- `/api/runs`
- `/api/admin`
- `/api/webhooks`

如果后续需要版本化，可以统一加前缀，但模块边界不要变。

---

## 2. 认证与会话

建议接口面覆盖：

- 登录
- 注册
- 登出
- 会话查询
- 会话刷新
- 找回密码
- 重置密码
- 邮箱验证
- 第三方绑定

这些接口主要服务认证页和登录态管理。

---

## 3. 当前用户

建议接口面覆盖：

- 当前用户资料
- 个人资料修改
- 偏好读取与更新
- 通知设置读取与更新
- 当前会话列表
- 会话注销
- 审计记录查询

这些接口主要服务账户页和设置页。

---

## 4. 内容与学习

### 4.1 内容侧

建议接口面覆盖：

- 内容包列表
- 内容包详情
- 课程目录
- 章节和课时
- 任务详情
- 资源元数据
- 发布版本
- 发布状态

### 4.2 学习侧

建议接口面覆盖：

- 学习总览
- 课程进度
- 课时进度
- 任务进度
- 进度事件上报
- 提交记录

这些接口主要服务 Web 的学习模块和 Desktop 的执行链路。

---

## 5. 商业化与授权

建议接口面覆盖：

- 商品列表
- 订单创建
- 订单查询
- 订单取消
- 支付状态查询
- 订阅查询
- 订阅续费
- 授权状态
- 设备绑定
- 设备解绑
- 授权历史

这些接口主要服务 Web 的会员和订单页，以及 Desktop 的授权流程。

---

## 6. 运行和提交

建议接口面覆盖：

- 运行请求创建
- 运行结果查询
- 运行日志查询
- 提交请求创建
- 提交历史查询
- 判题结果查询

这个模块面向 Desktop 和学习执行链路。

---

## 7. 管理面

建议接口面覆盖：

- 用户管理
- 内容管理
- 授权管理
- 系统状态
- 功能开关
- 审计日志

管理接口要和普通用户接口隔离开，不能混用同一套宽松权限。

---

## 8. 返回结构建议

为了让 Web 页面更容易消费，接口最好在主要响应中稳定带上：

- `data`
- `meta`
- `permissions`
- `status`
- `updatedAt`

列表接口再统一带分页信息：

- `page`
- `pageSize`
- `total`
- `hasMore`

---

## 9. 接口设计顺序

MVP 阶段建议先做这条顺序：

1. 认证和当前用户
2. 多租户和权限
3. 内容和学习只读查询
4. 订单、会员和授权
5. 运行和提交
6. 管理和审计
7. webhook 和后台任务

这样可以先把前端依赖的数据链路打通，再补重写动作。
