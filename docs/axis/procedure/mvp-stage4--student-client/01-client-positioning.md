# 01 - 学生客户端定位

**文档目的**：定义 ZENTRIX 学生客户端的产品身份、职责边界和设计原则，确保后续 UI、目录、运行与同步设计都围绕同一目标展开。

---

## 1. 核心定位

学生客户端是 Desktop 学习执行端，是用户完成课包学习的主工作台。

它的职责不是展示商业信息，也不是承载账户和购买流程，而是把学习过程组织成一个连续、可恢复、可同步的操作环境。

---

## 2. 客户端职责

### 2.1 应该做的事

- 打开已授权课包
- 浏览章节、课时、练习和资源
- 编辑代码或答案
- 运行、提交、查看结果
- 上报进度与完成状态
- 缓存内容并支持离线阅读

### 2.2 不应该做的事

- 注册、登录、找回密码等完整账户流程
- 课包购买、会员购买、订单管理
- 业务规则的最终裁决
- 进度、判题、成就、等级的权威写入

这些职责归 API。

---

## 3. 设计原则

- 内容优先：先有课包内容，再有交互外壳。
- 执行优先：用户主路径应始终围绕写、跑、提展开。
- 权威上收：最终状态以 API 为准，客户端只负责组织和呈现。
- 本地优先：可缓存内容尽量缓存，可离线浏览尽量离线可用。
- 连续上下文：运行、提交、错误和进度应始终回到当前课时上下文中。

---

## 4. 用户场景

- 学生从上次学习位置继续一节课。
- 学生在一个课时里反复修改、运行、提交。
- 学生网络不稳定，但仍要继续读内容和写草稿。
- 学生在授权失效或版本更新时明确知道下一步怎么做。

---

## 5. 约束

- 客户端必须与 Web 分离，不共享 Web 的页面语义。
- 客户端不应尝试取代 API 的权威地位。
- 客户端应尽量少跳页，多用工作台和上下文面板承接流程。
- 客户端后续可增强 IDE 能力，但主线不能被 IDE 化细节冲散。

---

## 6. 验收标准

- 能清楚说明客户端“做什么”和“不做什么”。
- 所有后续页面设计都能回溯到这里定义的边界。
- 学习主流程不会与账户、商业化、管理流程混在一起。

_本文档冻结学生客户端的职责边界，后续文档只在这个边界内展开。_
