# 04 - 同步、离线与缓存

**文档目的**：定义学生客户端的本地缓存、离线可用范围、同步队列和恢复策略，确保网络不稳定时学习过程仍然可继续。

---

## 1. 基本原则

- 本地缓存先于网络恢复体验。
- 运行和提交可以暂存，但权威结果仍以 API 为准。
- 离线状态下优先保留学习连续性，而不是强行阻断界面。
- 网络恢复后自动补发必要事件，并尽量合并到当前课时上下文。

---

## 2. 可缓存内容

建议缓存以下内容：

- 课包 `Manifest`
- 目录和课时元数据
- 文本课时内容
- 资源索引和可离线资源
- 用户本地草稿
- 最近一次运行结果摘要
- 最近一次提交结果摘要

不建议把权威业务状态只放在本地。

---

## 3. 离线行为

### 3.1 可以继续做的事

- 浏览已缓存课包
- 阅读课时内容
- 编辑本地草稿
- 查看最近历史结果
- 标记待同步动作

### 3.2 需要延后做的事

- 权威进度写入
- 远程判题确认
- 授权状态变更
- 内容版本更新确认

---

## 4. 同步队列

建议把以下动作纳入同步队列：

- 进度事件
- 提交事件
- 运行结果摘要
- 本地草稿保存点
- 缓存刷新请求

同步队列应支持：

- 排队
- 重试
- 去重
- 失败提示
- 恢复后自动重放

---

## 5. 恢复策略

- 启动时先检查本地缓存完整性。
- 网络恢复后优先补发进度和提交事件。
- 如果版本不匹配，先提示更新，再决定是否允许继续使用旧缓存。
- 如果授权失效，先保留只读能力，再限制提交和同步。

---

## 6. 状态提示

建议至少区分：

- 在线可用
- 离线可用
- 离线受限
- 同步中
- 同步失败
- 缓存过期
- 版本可更新

这些状态要在启动页、课包页、工作台和设置页保持一致。

---

## 7. 验收标准

- 网络断开后仍可继续核心学习动作。
- 网络恢复后，队列能自动补发并完成合并。
- 缓存与版本状态清楚，不会让用户误以为本地草稿已被权威保存。

_本文档冻结离线和同步边界，避免后续把本地状态误当作最终状态。_
