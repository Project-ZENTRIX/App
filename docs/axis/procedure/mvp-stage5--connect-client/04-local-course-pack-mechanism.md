# 04 - 本地课包机制

**文档目的**：定义 Desktop 如何把课包从“远端可见内容”变成“本地可学习内容”，并支持缓存、更新、校验和离线恢复。

---

## 1. 设计结论

本地课包不能只理解为下载目录。

它至少要包含：

- Manifest
- 课程文件
- 课时内容
- 资源引用
- 版本号
- 校验信息
- 本地索引
- 同步状态

Desktop 必须能在离线状态下继续读课包、看目录、打开已缓存课时，并在重新联网后恢复同步。

---

## 2. 本地课包的职责

### 2.1 读取

- 读取已授权课包的目录结构。
- 读取章节、课时、题目、资源和说明。
- 提供快速搜索和最近打开记录。

### 2.2 缓存

- 缓存课包元数据和正文。
- 缓存用户最近学习位置。
- 缓存已下载资源与必要附件。

### 2.3 更新

- 支持整包更新。
- 支持只更新 manifest 或局部文件。
- 支持版本比较和过期提示。

### 2.4 离线

- 在断网时继续访问已缓存内容。
- 对不可离线的资源显示清晰降级状态。
- 恢复联网后补同步学习进度和运行结果。

---

## 3. 建议的本地结构

建议为每个课包维护一个本地包目录，至少包含：

- `manifest.json`
- `content-index.json`
- `lessons/`
- `quizzes/`
- `assets/`
- `state/`
- `checksum.json`

其中：

- `manifest.json` 是入口。
- `content-index.json` 负责本地导航和快速索引。
- `state/` 只存本地学习态和恢复信息，不覆盖权威数据。

---

## 4. 同步规则

### 4.1 拉取规则

- 先拉 Manifest，再拉索引，再拉正文和资源。
- 任一层出现版本不匹配，先保守降级，不要直接覆盖本地态。

### 4.2 写回规则

- 用户在本地产生的学习进度、草稿和运行痕迹，要排队写回。
- 网络恢复后按顺序补发。
- 若服务器版本更高，应明确提示冲突，而不是静默覆盖。

### 4.3 校验规则

- 每次更新都要校验版本号与内容哈希。
- 本地缓存损坏时应可重新下载重建。
- 不要依赖单一文件作为唯一真相。

---

## 5. 与业务的关系

- Web 负责展示购买、拥有和可访问状态。
- API 负责返回权威课包和权限信息。
- Desktop 负责把已授权内容变成可持续学习的本地环境。

也就是说，本地课包是 Desktop 的学习基础设施，不是另一个内容源。

---

## 6. 目标结果

完成后，用户即使离线，也能在 Desktop 里继续学习已缓存课包；重新联网后，内容和进度又能回到可验证的一致状态。
