# 05 - Rust 后端实现逻辑

**文档目的**：定义 Tauri Rust 层在 stage5 里应该承担的职责边界、命令形态和本地系统集成逻辑。

**基本原则**：Rust 层不负责业务规则本身，但负责把操作系统能力、安全边界和本地状态管理做稳。

---

## 1. Rust 层的角色

Rust 后端应承担这些职责：

- Tauri 命令入口
- 文件系统访问
- 本地配置读写
- 本地缓存索引
- 进程与子进程控制
- 平台能力封装
- 安全敏感操作隔离

它不应该吞掉前端业务流程，也不应该把 API 逻辑重新写一遍。

---

## 2. 推荐命令类别

### 2.1 身份与授权

- 读取本地会话摘要
- 保存和清除桌面授权状态
- 读取设备指纹或本机标识
- 提供与 Web 授权接力相关的本地上下文

### 2.2 课包与缓存

- 列出本地课包
- 读取课包 manifest
- 下载或导入课包文件
- 校验本地课包版本
- 清理过期缓存

### 2.3 执行与运行

- 启动本地运行命令
- 停止运行进程
- 读取 stdout / stderr
- 上报运行结果摘要

### 2.4 系统集成

- 打开文件夹
- 读取最近路径
- 处理路径选择
- 管理平台相关特性差异

---

## 3. 状态管理原则

Rust 层应该管理的是“本地事实”：

- 设备配置
- 缓存目录
- 最近使用记录
- 运行进程句柄
- 授权摘要

这些状态要尽量轻，不要和 API 权威状态混在一起。

---

## 4. 错误处理原则

- 文件不存在要明确返回可恢复错误。
- 权限不足要明确提示需要用户操作。
- 进程失败要保留 stderr 和退出码。
- 任何涉及外部环境的失败都要可诊断，不要只给一个通用错误。

---

## 5. 与前端的接口关系

前端 React 负责：

- 展示状态
- 触发命令
- 组织工作流
- 处理用户输入

Rust 负责：

- 真正做本地 I/O
- 真正做系统调用
- 真正维护设备相关文件

两边的边界越清楚，后续维护成本越低。

---

## 6. 目标结果

完成后，Tauri 不再只是壳层，而是一个稳定的本地能力层，能支撑授权落地、课包缓存、运行执行和系统交互。
