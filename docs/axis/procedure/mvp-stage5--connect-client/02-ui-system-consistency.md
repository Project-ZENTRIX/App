# 02 - UI 系统一致性方案

**文档目的**：定义 Web 与 Desktop 之间共享的 UI 语义，避免两个端在颜色、状态、按钮、布局和组件命名上彼此脱节。

**当前方向**：Web 负责门户感，Desktop 负责工作台感，但它们必须共享同一套状态语言和基础视觉规则。

---

## 1. 设计结论

stage5 的 UI 不应该再分别长成两套完全不同的系统。

- Web 负责账户、课包、设备、授权和管理类页面。
- Desktop 负责学习执行、编辑、运行、提交和反馈。
- 两端共享相同的状态词、颜色语义、字体原则和组件命名。

用户应该能看出来它们是同一产品，不是两个互不认识的前端。

---

## 2. 一致性原则

### 2.1 共享语义

以下状态必须在两个端保持同义：

- 未登录
- 已登录
- 授权有效
- 授权失效
- 设备已绑定
- 课包已缓存
- 课包更新中
- 离线可用
- 同步中
- 同步失败
- 运行中
- 运行失败
- 提交中
- 判题中
- 已通过
- 未通过

### 2.2 共享结构

- 相同的主按钮层级
- 相同的状态标签写法
- 相同的信息密度原则
- 相同的空状态和错误提示风格
- 相同的图标规范，优先 Lucide

---

## 3. Desktop 视觉基线

Desktop 端应延续现有工作台风格：

- 密度适中
- 低装饰
- 信息清晰
- 状态驱动
- 不做营销页式排版

与 Web 相比，Desktop 可以更紧凑，但不能更花。

---

## 4. 推荐 token 方向

UI 颜色不必机械复刻，但语义应该对齐。

- 主色：用于主按钮、选中态、授权成功
- 强调色：用于继续、提交、关键行动
- 成功色：用于已绑定、已同步、已通过
- 警告色：用于过期、即将失效、等待处理
- 错误色：用于失败、拒绝、冲突
- 中性色：用于背景、边框、静态信息

Desktop 可以保留更偏技术工作台的底色，但不能用纯装饰色去替代状态。

---

## 5. 组件复用方向

建议把以下类组件做成可共享规范，必要时再抽共享实现：

- 顶部状态栏
- 左侧导航
- 列表行
- 课包摘要块
- 状态标签
- 错误提示条
- 空状态视图
- 进度信息区
- 授权卡片
- 设备卡片

不建议把编辑器、运行日志和复杂工作台布局硬塞进统一 UI 包里，应该只共享基础语义和壳层组件。

---

## 6. 布局原则

- Web 页面保持管理类布局，Desktop 保持工作台布局。
- 组件宽高、间距和响应式断点要稳定，避免加载后跳动。
- 状态文字不能依赖颜色单独表达。
- 图标按钮必须有明确标签或 tooltip。

---

## 7. 验收标准

- 用户能一眼分清这是同一产品的不同端。
- Web 和 Desktop 的状态词、色彩语义和交互反馈一致。
- Desktop 没有变成另一个风格系统。
- 组件复用能减少重复实现，而不是增加视觉冲突。

_本文档定义 stage5 的统一 UI 约束，后续页面和组件都应遵守。_
