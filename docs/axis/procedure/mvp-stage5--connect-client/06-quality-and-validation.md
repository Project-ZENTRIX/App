# 06 - 质量与验证

**文档目的**：定义 stage5 的验收标准、验证路径和回归边界，确保 Desktop 真的接上 Web、API、课包和本地能力。

---

## 1. 验收目标

stage5 的完成标准不是“页面能打开”，而是下面这些链路可以稳定跑通：

- Web 登录后可把授权交给 Desktop。
- Desktop 可以识别授权状态并进入学习工作台。
- Desktop 可以读取本地课包并在离线场景下继续使用。
- Desktop 的本地运行与反馈链路可以正常工作。
- UI 语义在 Web 和 Desktop 之间保持一致。

---

## 2. 关键验证场景

### 2.1 身份与授权

- Web 登录成功。
- 发起 Desktop 授权。
- Desktop 完成接收和落地。
- 取消授权后 Desktop 退回未授权状态。

### 2.2 课包加载

- 拉取课包索引。
- 缓存课包正文。
- 本地打开已缓存课时。
- 版本过期后提示更新。

### 2.3 离线恢复

- 断网后仍可访问已缓存内容。
- 本地修改可排队等待同步。
- 恢复网络后可补发进度和结果。

### 2.4 Rust 层

- 本地文件读写正常。
- 运行命令可回收 stdout / stderr。
- 失败路径能返回可诊断错误。

---

## 3. 测试建议

- 先做单元测试，覆盖授权状态、缓存索引和命令解析。
- 再做组件测试，覆盖桌面授权页、工作台状态和错误提示。
- 再做端到端测试，覆盖 Web -> Desktop 的授权接力和课包加载。
- 最后做少量手工验证，检查平台差异和真实文件系统行为。

---

## 4. 风险控制

- 不要把“授权成功”只做成前端状态，要确认后端和本地都落地。
- 不要把本地课包当作权威真相，权威仍然在 API。
- 不要让 Rust 层持有过多业务规则，避免后续扩散成第二个后端。
- 不要让 UI 只在理想网络条件下可用。

---

## 5. 最终判断

如果一个新用户能在 Web 登录，然后在 Desktop 成功接权、打开课包、离线继续学习、恢复联网后继续同步，这个阶段才算真正完成。
