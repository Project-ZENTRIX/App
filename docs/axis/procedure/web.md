# Project ZENTRIX — Web 开发计划

**文档目的**：基于 `design/web-ui.md` 的 Web UI 设计草案，拆解 Web 端开发的执行顺序、阶段目标与验收点，作为前端实现计划。

---

## 1. 计划原则

- 先完成信息架构与通用布局，再实现具体页面。
- 先实现登录后高频页面，再补充营销与增强页面。
- 先对接只读展示，再对接需要写入状态的交互。
- 先对齐 API 返回结构，再做视觉优化和交互细化。

---

## 2. 阶段一：项目骨架与公共布局

### 2.1 目标

- 建立 Web 项目结构、路由和基础布局。
- 完成导航、页脚、用户菜单和通用状态组件。
- 统一页面容器、空状态、加载态与错误态。

### 2.2 计划步骤

1. [x] 搭建 Web 路由结构和公共布局。
2. [x] 实现顶部导航、侧边栏和页脚基础组件。
3. [x] 实现统一的按钮、标签、卡片、表格和弹窗样式。
4. [x] 预置登录态判断和全局加载状态。
5. [x] 建立空状态、错误状态与权限不足提示组件。

### 2.3 验收点

- 所有页面共享一致的视觉骨架。
- 通用组件可以被后续页面直接复用。

---

## 3. 阶段二：认证入口与账户流程

### 3.1 目标

- 完成注册、登录、找回密码和会话失效处理页面。
- 为后续账号安全设置和第三方绑定预留入口。

### 3.2 计划步骤

1. [x] 实现登录页、注册页和找回密码页。
2. [x] 对接认证接口并处理表单校验错误。
3. [x] 实现会话过期、登录失败和邮箱未验证提示。
4. [ ] 预留第三方登录与账号绑定区域。
5. [x] 完成登录后跳转逻辑与重定向处理。

### 3.3 验收点

- 用户可以完成完整的注册、登录和找回密码流程。
- 登录失败、重复注册和验证失败有明确反馈。

---

## 4. 阶段三：首页控制台与个人中心

### 4.1 目标

- 构建登录后的默认首页。
- 完成个人资料、安全设置、通知设置和会话管理。

### 4.2 计划步骤

1. [x] 实现首页控制台概览卡片和快捷入口。
2. [x] 实现最近访问、进度总览和成就摘要模块。
3. [x] 实现个人资料编辑页。
4. [x] 实现密码修改、通知设置与会话管理页面。
5. [x] 对接当前用户与个人中心 API.

### 4.3 验收点

- 控制台能展示用户的关键状态与入口。
- 个人设置页可以完整读写资料和偏好。

---

## 5. 阶段四：课包市场与详情页

### 5.1 目标

- 完成课包浏览、筛选、搜索和详情查看体验。
- 为购买决策提供明确的内容、权益和价格信息。

### 5.2 计划步骤

1. [ ] 实现课包市场列表页。
2. [ ] 实现筛选、搜索和排序控件。
3. [ ] 实现课包详情页、目录预览和权益说明模块。
4. [ ] 实现购买入口与购买确认弹窗或抽屉。
5. [ ] 对接课包与内容查询 API。

### 5.3 验收点

- 用户可以快速浏览、筛选并进入课包详情。
- 详情页能够承接购买决策并展示关键权益信息。

---

### 6.1 目标

- 展示已购课包、可学习资产与会员权益。
- 支持续费、开通和权益查看。

### 6.2 计划步骤

1. [ ] 实现我的课包列表页与状态标签。
2. [ ] 实现会员中心页面、权益列表和套餐对比表。
3. [ ] 实现续费、开通和权益说明入口。
4. [ ] 实现空状态与过期状态提示。
5. [ ] 对接订单和订阅 API。

### 6.3 验收点

- 用户可以清楚看到自己拥有哪些课包和会员权益。
- 课包和会员的到期、过期和未开通状态展示明确。

## 7. 阶段六：订单中心

### 7.1 目标

- 提供订单列表、订单详情和支付状态查询。
- 覆盖待支付、支付失败和取消订单等常见场景。

### 7.2 计划步骤

1. [ ] 实现订单列表页与筛选条件。
2. [ ] 实现订单详情页和状态流转展示。
3. [ ] 实现继续支付、取消订单和支付结果提示。
4. [ ] 对接支付与订单 API。
5. [ ] 处理空订单和异常订单状态。

### 7.3 验收点

- 用户可以查看并操作自己的订单。
- 支付失败和待支付状态有清晰的处理入口。

---

- 完成 Desktop 授权状态展示和设备绑定流程。
- 支持解绑、授权记录查看和异常提示。

### 8.2 计划步骤

1. [ ] 实现授权状态卡和设备列表页。
2. [ ] 实现绑定码输入、绑定确认与结果反馈。
3. [ ] 实现解绑确认弹窗和成功反馈。
4. [ ] 实现授权历史记录展示。
5. [ ] 对接授权与设备 API。

### 8.3 验收点

- 用户可以完成设备绑定和解绑。
- 授权范围、数量限制和到期时间展示清晰。

---

## 9. 阶段八：成就与进度

### 9.1 目标

- 完成只读进度总览、成就墙、等级和勋章展示。
- 展示用户学习结果和阶段性成果。

### 9.2 计划步骤

1. [ ] 实现成就墙与勋章展示页面。
2. [ ] 实现等级展示和经验进度模块。
3. [ ] 实现学习进度总览与明细面板。
4. [ ] 实现最近同步时间和关联课包展示。
5. [ ] 对接成就、等级和进度 API。

### 9.3 验收点

- 用户可以查看自己的学习结果和成长状态。
- 进度展示为只读，不与学习执行混淆。

---

## 10. 阶段九：营销页与增强页面

### 10.1 目标

- 补齐公开首页、FAQ、公告和其他说明型页面。
- 为后续商业化和内容展示扩展预留空间。

### 10.2 计划步骤

1. [ ] 实现公开首页和产品介绍区。
2. [ ] 实现价格方案与常见问题页面。
3. [ ] 实现帮助、协议和隐私入口。
4. [ ] 预留评价、推荐和内容作者展示区域。
5. [ ] 统一营销页与登录后控制台的视觉区分。

### 10.3 验收点

- 未登录用户可以理解产品定位与购买入口。
- 营销页与控制台有清晰的页面边界。

---

## 11. 阶段十：联调与体验收尾

### 11.1 目标

- 完成与 API 的端到端联调。
- 收敛状态、错误提示、空状态和加载体验。

### 11.2 计划步骤

1. [ ] 联调认证、首页、课包、订单、会员、授权与进度页面。
2. [ ] 校对接口字段、分页结果和状态标签文案。
3. [ ] 统一错误提示、空状态和加载态。
4. [ ] 检查响应式布局和主要断点表现。
5. [ ] 根据联调结果优化页面交互和信息密度。

### 11.3 验收点

- Web 核心页面可以独立完成主要业务路径。
- 页面状态与 API 状态保持一致，用户不会看到断裂的流程。

---

2. 认证入口与账户流程
3. 首页控制台与个人中心
4. 课包市场与详情页
5. 我的课包与会员中心
6. 订单中心
7. 设备与授权
8. 成就与进度
9. 营销页与增强页面
10. 联调与体验收尾

---

## 13. 计划边界

- 本计划只描述 Web 端开发步骤，不涉及具体工时。
- 计划以 `design/web-ui.md` 为主，必要时与 API 设计同步调整。
- 若后续增加移动端、运营后台或更多营销能力，应另行补充独立计划。
