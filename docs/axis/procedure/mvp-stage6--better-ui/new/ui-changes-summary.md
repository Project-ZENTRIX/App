# Stage 6 UI 变动总结

本阶段目标不是重做信息架构，而是把 `zentrix-web` 这套页面从“单一壳 + 静态页面集”整理成一套更完整、更一致、可按身份展示权限的产品界面。

如果要直接推进实现，先看 [ui-task-breakdown.md](docs/axis/procedure/mvp-stage6--better-ui/new/ui-task-breakdown.md)。

## 1. 统一外壳要补齐的变化

- 继续沿用左侧栏 + 顶部栏 + 主内容区的布局，但把它当成全站统一壳，不再让每个页面各写一套独立导航。
- 左侧栏需要保留分组结构：`仪表盘 / 学习 / 账户 / 管理 / 设置`。
- 顶部栏需要保持面包屑、通知、帮助、用户菜单这些全局入口，并保证在不同页面里标题与当前位置一致。
- 移动端需要保留侧栏抽屉式展开收起，主内容区不被侧栏挤压。

## 2. 侧栏权限控制要加的内容

- 左侧栏不是所有人看到同一套菜单，需要按当前身份做权限展示。
- `管理` 分组应按权限决定：
  - 有权限时正常显示 `管理员`、`内容包` 等入口。
  - 无权限时隐藏整组，或以禁用态/锁定态展示，避免误导用户可点击。
- `账户`、`学习` 这些基础分组可继续显示，但其中细项也要支持按身份裁剪。
- 侧栏底部的用户信息需要反映当前登录角色，不要固定写死成“管理员”。
- 如果采用“可见但不可用”的方案，建议配合锁定图标、灰态样式或权限说明，让用户知道是权限不足而不是页面故障。

## 3. 页面层级与内容形态要调整的地方

### 总览 / 仪表盘

- 首页要强调关键指标卡、最近状态、快捷入口，而不是只放静态介绍。
- 管理员、教师、学生三类首页都要保持同一视觉语言，但内容重心不同。
- 首页按钮区需要支持“继续学习”“学习计划”“内容包工作区”等身份相关操作。

### 列表页

- 课程、内容包、设备、订单、资料库这类页面统一成“标题 + 说明 + 筛选/新建动作 + 表格/卡片列表”的结构。
- 列表页要补搜索框、筛选按钮、状态 badge、行内操作按钮，减少纯文本列表。
- 表格区域需要支持横向滚动，避免窄屏下挤压列内容。

### 详情页

- 课程详情、内容包详情、设备详情、订单详情要统一成“概览区 + 明细区 + 操作区”的模式。
- 详情页应突出状态、版本、授权、支付、最近更新时间等高频信息。
- 需要保留返回列表、版本管理、撤回、解绑、审核等动作入口。

### 设置页

- 个人资料、通知、安全、会话要采用子导航 tabs，而不是独立散落的页面。
- 设置页要更偏表单与管理操作，减少营销式展示。
- 会话页需要保留可撤销当前会话、全部退出这类高风险操作，并用表格呈现登录设备信息。

### 管理页

- 管理员工作区要更像控制台：用户管理、内容包审核、系统状态、许可证概览都要以卡片和指标形式集中呈现。
- 管理页要突出特权入口，不要混在普通学习页里。

### 学生 / 教师变体页

- 学生侧页面要更聚焦“进度、课程、设备、订单、会员”等个人学习场景。
- 教师侧页面要更聚焦“内容包编写、发布、审核流转”等创作场景。
- 三类身份页面应共享组件风格，但信息密度和动作优先级不同。

## 4. 组件与视觉一致性需要补的点

- 所有页面统一使用同一套卡片、徽章、按钮、表格、标签页样式。
- 页面标题区统一为“标题 + 副标题 + 动作按钮”，避免每页排版漂移。
- 列表和详情页都应保留明确的状态标签，不能只靠颜色区分。
- 空间密度要偏产品后台风格，少装饰，多可扫描信息。

## 5. 这阶段最终要达成的 UI 结果

- 进入不同身份后，侧栏内容会按权限变化。
- 管理、教师、学生三类任务入口一眼可区分。
- 列表、详情、设置、管理四类页面形成稳定模板。
- 全站导航、标题层级、操作区和状态展示保持一致。
