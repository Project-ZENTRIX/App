# Project ZENTRIX - Stage 3 课包内容系统设计

**文档目的**：设计一套不依赖数据库 `ROW` 作为主载体的课包内容系统，供当前后端和未来本地客户端共同复用。重点覆盖课包 `Manifest`、课程文件、测验模板，以及面向多租户的三角色初期计划。

**设计边界**：

- 这里讨论的是“课包内容层”，不是课包购买、支付、授权、进度等运行层。
- 数据库仍然保留用户、租户、订阅、购买、进度等运行态记录，但不作为课程内容本体的唯一来源。
- 课包内容应优先以文件化、可版本化、可离线复用的方式组织。

---

## 0. 设计目标

- 让课包内容可以独立于数据库迁移、缓存和运行环境存在。
- 让本地客户端可以直接读取课包包体，而不依赖后端逐行拼装。
- 让课包内容的结构可以和数据库中的基础元数据对齐，但又保留更多面向教学和编辑的扩展信息。
- 让课程、测验、作业、资源、版本和发布状态有稳定的文件约定。
- 为多租户场景预留学生、教师、管理员三类角色的权限与工作流。

## 2. 总体原则

- 内容与运行解耦：课程内容可以单独导出、同步和缓存。
- 版本先行：所有内容都必须有 `version` 和 `contentId` 约束。
- 数据库对齐但不绑死：Manifest 与数据库字段保持映射关系，但允许附加教学元数据。
- 本地优先：客户端应可直接加载文件包并离线浏览目录、课时、测验和资源。
- 可增量更新：支持整包发布，也支持局部文件替换和校验。

---

## 3. 建议落地顺序

1. 先冻结 Manifest 规范，明确课包内容包的根对象。
2. 再定义课程文件、资源引用和目录组织方式。
3. 然后定义测验模板，让题型与编辑器、渲染器统一。
4. 最后补齐多租户三角色的权限模型、内容管理边界和同步策略。

---

## 4. 目标交付物

- 一份课包内容 `Manifest` 规范
- 一套课程文件与资源文件组织规范
- 一套可复用的测验模板定义
- 一份多租户三角色的初期计划
- 一组未来可直接给本地客户端消费的稳定 JSON / Markdown 约定
