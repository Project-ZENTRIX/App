# Project ZENTRIX — 技术说明（Technicals）

**状态**：草案

## 2. 各端技术决策

### 2.1 API

- **框架**：NestJS。
- **运行时**：基于 Node.js 运行。
- **职责对应**：承载全部业务规则、数据权威、代码沙箱执行、判题、进度计算等（详见 [Responsibility.md](responsibility.md)）。

### 2.2 Web

- **框架**：Next.js。
- **主要职责**：账户、授权、课包/会员购买与管理、成就展示、学习进度总览等非深度学习交互功能。
- **部署**：Vercel。

### 2.3 Desktop App

- **框架**：Tauri（后端） + React（前端界面）。
- **目标平台优先级**：Windows → macOS → Linux。
- **核心定位**：唯一的学习执行端，提供最大限度贴近真实开发的体验。
- **关键能力方向**：
    - 集成 IDE 相关操作（编辑、运行反馈、项目管理等）
    - 在业务允许范围内支持本地资源与文件系统相关能力
    - 离线学习支持（进度最终仍以 API 为准）

### 2.4 共享与工程

- **Monorepo**：采用 Turborepo 管理 API、Web、Desktop 及共享代码。
- **共享层**：React 组件、类型定义、API 客户端、工具函数等尽量抽离复用，减少双端重复。

---

## 3. 关键技术决策说明

### 3.1 代码执行方式

- **确定方案**：全部用户代码执行均通过**后端沙箱**完成。
- Desktop 端不承担最终权威运行与判题，仅负责编辑、提交与结果展示。
- 目标是在安全可控的前提下，仍通过 IDE 集成操作尽量还原真实开发感受。

### 3.2 认证与数据库

- 数据库采用 **PostgreSQL + Prisma** 连接。
- PostgreSQL 作为项目主数据库，用于存储用户、课包、进度、订单、成就等核心业务数据。
- 认证方案采用 **项目自实现 Auth**，其核心数据结构为 `user`、`session`、`account`、`verification`。
- 认证域数据与业务域数据分离，便于登录态、第三方绑定与验证流程独立演进。

### 3.3 AI 辅助（第二期）

- 采用 **BYOK（Bring Your Own Key）** 模式。
- 由用户自行配置 API Key，平台不统一托管模型调用费用。
- 初期定位为简单的对话协助功能。

### 3.4 真实开发体验

- Desktop 端需尽可能集成常见 IDE 操作与工作流，降低「学习环境」与「真实开发环境」之间的割裂感。
- 具体集成深度（例如本地终端、调试器、扩展生态等）将在实现阶段进一步评估。

## 4. 部署与基础设施（当前倾向）

- **Web**：Vercel。
- **API**：生产环境运行于 Node.js，具体托管平台待进一步确认（需与 NestJS + 沙箱执行需求匹配）。
- **数据库**：PostgreSQL，应用层通过 pg 直连。
- **收款**：爱发电（业务侧接入，技术实现细节后续补充）。

---

## 5. 约束与排除项

- 不使用 Vue 及其相关技术栈。
- 组织级授权功能当前阶段不纳入。
- Linux Desktop 支持优先级最低，放在 Windows 与 macOS 之后。

---

## 6. 与职责文档的关系

本技术选型服务于 [Responsibility.md](responsibility.md) 中定义的三端职责边界：

- API 作为唯一业务与数据权威。
- Web 专注账户与商业化门户。
- Desktop 专注学习执行与真实开发体验。

任何技术实现均不得突破既定职责边界。
