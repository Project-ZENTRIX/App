# Project ZENTRIX — 职责划分（Responsibility）

本文档仅定义 API、Web、Desktop App 三端的职责边界，不涉及实现流程、技术架构与交互时序。

---

## 一、总体原则

1. **API** 是业务规则与数据的唯一权威来源。
2. **Web** 承担账户、商业化与非学习类管理职责。
3. **Desktop App** 承担具体课包内的学习执行职责。
4. 任何业务状态的最终变更，均以 API 为准。
5. Web 与 Desktop App 均不得绕过 API 直接修改权威数据。

---

## 二、API 职责

- 用户账户体系的完整管理（注册、登录、鉴权、权限、角色）
- 课包、会员商品与订单的权威数据管理
- 学习进度、成就、等级等业务数据的存储与计算
- 代码执行、判题与结果校验的权威处理
- 内容（课程、章节、题目、测试用例等）的存储与下发控制
- 跨端数据一致性保障
- 安全、限流、审计与基础运维能力

---

## 三、Web 职责

### 3.1 账户与授权相关

- 用户注册、登录、找回密码
- 账户信息管理
- Desktop 端授权与设备管理

### 3.2 商业化相关

- 课包浏览、购买
- 会员购买与管理
- 订单查询与管理
- 已购课包列表与资产展示

### 3.3 非学习类展示与管理

- 成就系统展示
- 等级与勋章展示
- 学习进度总览（只读）
- 个人中心与基础设置

### 3.4 明确不承担的职责

- 具体课包内的编码、运行、提交与进度推进
- 课包内容的深度学习交互

---

## 四、Desktop App 职责

### 4.1 学习执行相关

- 已授权课包的打开与学习
- 代码编辑、本地/云端运行
- 题目提交与结果反馈
- 学习进度的推进与上报
- 课包内笔记、练习等学习行为

### 4.2 本地增强相关

- 离线学习支持（在 API 授权范围内）
- 本地资源与文件系统相关能力（在业务允许范围内）

### 4.3 明确不承担的职责

- 用户注册与完整账户体系管理
- 课包与会员的购买、支付
- 订单与商业化管理
- 成就与等级的规则计算（仅负责触发与上报）

---

## 五、职责边界补充说明

| 事项                | 归属端   | 备注                     |
| ------------------- | -------- | ------------------------ |
| 账户注册 / 登录     | Web 为主 | Desktop 仅做轻量登录支持 |
| Desktop 授权        | Web      | -                        |
| 课包购买 / 会员购买 | Web      | -                        |
| 已购课包管理        | Web      | Desktop 只读展示         |
| 成就 / 等级展示     | Web      | Desktop 负责触发上报     |
| 具体课包学习行为    | Desktop  | 严格限定                 |
| 学习进度权威数据    | API      | 两端仅展示或上报         |
| 代码判题权威结果    | API      | -                        |
