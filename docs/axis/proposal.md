# Project ZENTRIX — 项目提案（Proposal）

**文档版本**：初始版  
**日期**：2026-07-26  
**状态**：草案

---

## 1. 项目概述

**项目名称**：Project ZENTRIX

**一句话愿景**：让所有人都能学编程。

ZENTRIX 是一个面向真实开发体验的代码学习平台，通过 Desktop 端提供接近专业开发环境的学习路径，帮助学习者从入门到能够进行实际项目实践。平台以自研课包为核心，早期聚焦体系化与 PBL（项目式学习）内容，远期开放第三方内容入驻。

---

## 2. 目标用户

| 优先级 | 用户群体 | 说明                   |
| ------ | -------- | ---------------------- |
| P0     | 在校学生 | 核心目标用户，优先服务 |
| P1     | K12 学生 | 次优先级，后续逐步覆盖 |
| -      | 其他群体 | 当前阶段暂不考虑       |

---

## 3. 问题与机会

当前市场上多数代码学习产品存在明显的「非专业化」倾向：学习环境与真实开发场景脱节，学习者难以建立对专业开发流程的直观认知。

ZENTRIX 的核心机会在于：

- 提供更接近真实开发环境的学习体验（以 Desktop 端为主阵地）
- 通过体系化自研课包 + PBL 项目，帮助学习者完成从「学语法」到「做项目」的跨越
- 保持内容专业性的同时，降低真正想学编程的人群的入门与持续学习门槛

---

## 4. 产品定位

- **学习执行端**：Desktop App（优先 Windows / macOS，Linux 后续支持）
- **账户与商业化门户**：Web
- **业务与数据权威**：API

学习行为严格限定在 Desktop 端完成，Web 端不承担具体课包内的编码、运行与进度推进职责。详细职责边界见《Responsibility.md》。

---

## 5. 内容策略

- **早期**：以自研课包为主，包含体系化课程与 PBL（项目式学习）类型内容。
- **远期**：开放第三方内容入驻。
- **语言支持**：无强制限制。理论上 Desktop 端所能支持的语言均可纳入，优先覆盖主流教学与实用语言。

---

## 6. 功能范围

### 6.1 第一期（MVP）核心范围

以「学习模块」为绝对核心，确保用户能够完成完整的课包学习闭环。

重点包括：

- 课包打开与学习流程
- 代码编辑、运行与提交
- 学习进度推进与基础反馈
- 与 API 的进度同步

商业化、成就体系、AI 辅助等功能在数据模型与接口层面预留必要字段，但完整实现放至后续阶段。

### 6.2 第二期及以后

- 会员体系与课包单独订阅的完整商业化流程
- 成就、等级与勋章系统
- 简单的 AI 对话协助功能
- 第三方内容入驻相关能力
- Linux 桌面端支持
- 其他体验优化与扩展功能

---

## 7. 商业模式

- **主要模式**：会员订阅 + 课包单独购买/订阅
- **组织级授权**：当前阶段暂不考虑
- **收款渠道**：接入爱发电

Web 端负责课包浏览、购买、会员管理与订单相关能力；实际学习消费发生在 Desktop 端。

---

## 8. 平台职责摘要

| 端          | 核心职责概要                                        |
| ----------- | --------------------------------------------------- |
| API         | 业务规则、数据权威、判题、进度与内容控制            |
| Web         | 账户、授权、课包/会员购买与管理、成就展示、进度总览 |
| Desktop App | 具体课包学习执行、代码编辑运行、进度上报、离线支持  |

详细职责划分以《Responsibility.md》为准。

---

## 9. 对标参考

当前无明确直接竞品。产品形态可参考 CodeHS 一类面向教学的结构化学习平台，但在学习环境专业性与真实开发体验上形成差异化。

---

## 10. 阶段性目标（高层）

1. **MVP 阶段**：完成以学习模块为核心的可用版本，覆盖 Windows 与 macOS，支持自研课包的完整学习流程。
2. **增长阶段**：完善商业化（会员 + 课包订阅）、成就体系，并上线基础 AI 对话协助。
3. **扩展阶段**：引入第三方内容、完善 Linux 支持，持续优化真实开发体验。
